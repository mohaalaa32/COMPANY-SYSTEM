## 2. فحص مسار API الفعلي للشركة ونتائج الاستكشاف (Live Endpoint Exploration & Probe)

زودنا صاحب المشروع بالعنوان الفعلي المعتمد للأسعار:
`http://192.168.1.1:1001/ords/talbaghdad/talbaghdad/matprice`

### أ) التحليل المعماري للمسار (Architecture & Endpoint Analysis):
- **التقنية المستخدمة:** الواجهة مبنية على خدمات أوراكل للبيانات عبر REST المعيارية: **Oracle REST Data Services (ORDS)**.
- **نمط المسار في أوراكل:** `/ords/{schema}/{workspace_or_module}/{template}`:
  - `schema`: `talbaghdad`
  - `module`: `talbaghdad`
  - `template`: `matprice` (اختصار لـ Material Price / تسعيرة المواد والأصناف).
- **المنفذ والبروتوكول:** يعمل الخادم عبر بروتوكول HTTP على المنفذ المخصص `1001`.
- **طبيعة العنوان (RFC 1918 Private IP):** العنوان `192.168.1.1` هو عنوان شبكة محلية خاصة (Internal LAN / Gateway)، ولا يمكن الوصول إليه عبر شبكة الإنترنت العامة دون اتصال بالشبكة المحلية ذاتها أو عبر شبكة افتراضية خاصة (VPN).

### ب) نتائج فحص الاتصال بالقراءة فقط (Single Bounded GET Probe Results):
- **طريقة الفحص:** تم تنفيذ طلب استكشافي واحد بصيغة GET بمهلة زمنية محدودة (8000ms)، ودون تتبع تحويلات تلقائية، ودون مسح للشبكة أو تخمين لمسارات إضافية.
- **النتيجة المرصودة:** `REQUEST_FAILED AbortError: This operation was aborted` (TCP Connection Timeout).
- **التشخيص الدقيق:**
  1. **فشل طبقة الشبكة (Network / Routing Layer):** انقضت مهلة الاتصال دون إتمام مصافحة TCP (SYN-ACK)، مما يعني أن جهاز التطوير الحالي غير متصل بالشبكة المحلية الخاصة بالشركة (`192.168.1.0/24`)، أو أن المنفذ `1001` على ذلك الجهاز غير موجه خارجياً.
  2. **التمييز عن أخطاء المصادقة أو الخادم:** الفشل **ليس رفض مصادقة HTTP (401 Unauthorized أو 403 Forbidden)**، كما أنه **ليس خطأ في تطبيق الخادم (500/502/503)**؛ إذ لم تصل حزم الطلب إلى خادم ORDS أصلاً لعدم وجود مسار شبكي.

### ج) ضوابط الأمان ومتطلبات الوصول (Security & Network Policy):
- **حظر تعريض النظام للإنترنت:** يُمنع منعاً باتاً فتح منافذ الراوتر (Port Forwarding) لتعريض خادم أوراكل أو المنفذ `1001` مباشرة لشبكة الإنترنت العامة لما يمثله ذلك من تهديد أمني لقواعد بيانات الشركة.
- **الحلول المعتمدة للربط:**
  1. **الخيار الأول (الاتصال بالشبكة المحلية أو VPN):** توصيل جهاز التطوير/الخادم بشبكة الشركة المحلية عبر الـ Wi-Fi/LAN الخاص بالشركة، أو تفعيل نفق VPN رسمي ومصرح به يربط الجهاز بالشبكة الداخلية `192.168.1.x`.
  2. **الخيار الثاني (تصدير عينة JSON محلياً):** يقوم مسؤول النظام أو موظف متواجد على نفس الشبكة المحلية بفتح المسار عبر المتصفح أو تطبيق Postman:
     `GET http://192.168.1.1:1001/ords/talbaghdad/talbaghdad/matprice`
     وتصدير عينة الاستجابة الناتجة (JSON) وحفظها محلياً في مجلد الاختبارات المعزول لتطوير المحول الحقيقي `RealSalesAdapter` واختباره دون الحاجة لاتصال حي مستمر.

### د) ماذا يوفر هذا المسار وماذا ينقصه لفرع كربلاء؟ (Gap Analysis):
1. **ما يوفره المسار مبدئياً:**
   - جدول تسعيرة المواد والأصناف (`matprice`) الصادر من نظام أوراكل.
   - هيكل استجابة أوراكل القياسي المتوقع (عادة كائن يحتوي على مصفوفة `items` وعناصر التصفح `hasMore`, `limit`, `offset`, `count`, `links`).
2. **ما ينقصه وما يحتاج حسماً مع مسؤول النظام:**
   - **تصفية فرع كربلاء:** هل مسار `matprice` يرجع الأسعار العامة فقط، أم يقبل معاملاً لتحديد الفرع (مثل `?branch=karbala` أو `?branch_id=...`)؟
   - **بيانات المخزون:** هل كميات المخزون المتوفرة للبيع بفرع كربلاء متضمنة داخل سجلات `matprice` (كحقل كمية)، أم توجد خدمة منفصلة للمخزون (مثل `matstock` أو `inventory`)؟
   - **المواصفات والضمان:** هل يحتوي `matprice` على مواصفات الأجهزة (الذاكرة، الرام، اللون، الكاميرا، وشهور الضمان)، أم أنه يقتصر على الكود والاسم والسعر؟
   - **نظام التصفح بالصفحات (Pagination):** ما هو الحد الأقصى للصفحة الواحدة (`limit`) وكيف يتم جلب باقي الأصناف؟
   - **آلية المصادقة عند توفر الاتصال:** هل مسار ORDS مفتوح على الشبكة الداخلية أم يتطلب توكن OAuth2 من مسار `/ords/talbaghdad/oauth/token` أو Basic Auth؟

## 3. المعلومات المطلوبة لربط نظام المبيعات وفق عقود المحولات (`ISalesAdapter`)

استناداً إلى عقود النظام المعتمدة في `docs/CONTRACTS.md §1` و `packages/adapters/src/types.ts`، يتطلب ربط كتالوج الشركة وأسعارها ومخزونها لفرع كربلاء استيفاء البنود التالية:

### أ) هوية وتصنيف المنتجات (Product Identity & Catalog Scope):
- **معرف الصنف المستقل (SKU / Barcode):** يجب أن يمتلك كل منتج معرفاً فريداً ومستقلاً يحدد الطراز، وسعة الذاكرة، واللون بدقة. يُمنع منعاً باتاً دمج أصناف متباينة في المواصفات تحت معرف واحد.
- **الاسم المعتمد:** الاسم الرسمي بالعربية (`nameAr`) وبالإنجليزية (`nameEn`).
- **الفئة والماركة:** تصنيف الجهاز (`phone`, `tablet`, `accessory`, `audio`, `wearable`) واسم الماركة الصريح (`Apple`, `Samsung`, `Xiaomi`, `Infinix`، إلخ).
- **الوسوم ومجالات الاستخدام:** أي وسوم تدعم أغراض الاستخدام (مثل: `gaming`, `student`, `best-camera`).

### ب) الأسعار، التكلفة، والعملة (Pricing & Margin Protection):
- **الأسعار:** سعر البيع الأساسي (`basePriceIQD`)، وسعر الخصم المعلن إن وجد (`salePriceIQD`).
- **سعر التكلفة الداخلي (`costIQD`):** مطلوب لاستخدامه حصراً من قبل محرك الحسابات القطعي (`@tel/calc`) لضمان عدم انتهاك الحد الأدنى للهامش الربحي (`minMarginPct`). يُعزل هذا الحقل تماماً ولا يظهر للعميل أو للواجهات الأمامية.
- **العملة والضريبة:** تأكيد أن الأسعار بالدينار العراقي (IQD)، وتوضيح ما إذا كانت الأسعار تشمل ضريبة المبيعات/الرسوم، أم تحتاج تحويلاً من عملة أخرى (كالـ USD).

### ج) مخزون فرع كربلاء وتوقيت البيانات (Karbala Stock & Latency):
- **معرف فرع كربلاء:** المعرف الرقمي أو النصي المعتمد لفرع كربلاء في نظام الشركة (لمطابقته مع `branch-karbala`).
- **طبيعة المخزون:** تحديد ما إذا كان الرقم المرجع يمثل «المخزون الإجمالي في الرف» أم «المخزون المتاح للبيع الفعلي بعد خصم المحجوز».
- **تحديث البيانات:** هل استعلام المخزون يتم لحظياً عبر API مباشر (On-demand)، أم يتطلب تخزيناً مؤقتاً (Cache TTL) محدد المدة، أم يرسل النظام إشعارات (Webhooks) عند تغير كميات الأصناف؟

### د) المواصفات، الضمان، ومصدر التجهيز (Specs & Agency):
- **المواصفات الفنية:** السعة التخزينية (Storage)، الذاكرة العشوائية (RAM)، المعالج (Processor)، الشاشة (Screen)، الكاميرا (Camera)، وسعة البطارية (Battery).
- **الضمان الرسمي (`warrantyMonths`):** تحديد مدة الضمان بالأشهر من حقل صريح ومستقل في بيانات الشركة. **يُحظر استنتاج الضمان أو نوعه من اسم المنتج**.
- **وكالة التجهيز ومصدر البضاعة:** إذا كانت الشركة توفر حقولاً للوكالة الرسمية أو الموزع المعتمد، تُربط كما هي، وإلا تُترك غير محددة بأمان ولا يتم اختلاقها.

### هـ) إمكانات وقدرات الواجهة البرمجية (API Capabilities):
- **القراءة (Read Capabilities):** استرجاع الكتالوج، وتفاصيل المنتج، والمخزون، والعروض النشطة.
- **الكتابة والحجز (Write / Transactional Capabilities):** يجب التحقق مما إذا كان API الشركة يدعم حجز المخزون مؤقتاً (`reserveStock`) أو إنشاء مسودة طلب، **أم أن API مخصص للاستعلام والقراءة فقط**. لا يجوز افتراض وجود ميزات حجز أو كتابة قبل ثبوتها في وثائق الشركة.

## 7. المسارات المستقلة الممكن متابعتها أثناء انتظار عينة/اتصال الشركة (Feasible Tracks)

أثناء انتظار رد مسؤول نظام الشركة أو تصدير عينة JSON، يمكن متابعة الأعمال المستقلة التالية دون المساس ببيانات الربط:
1. **هندسة واجهات العميل ولوحة الموظفين (Phase 1):** تحسين تجربة المستخدم على شاشات الموبايل، حالات التحميل التفاعلية، ودعم إمكانية الوصول (A11y).
2. **محاكاة حالات فشل الشبكة والمهل (Resilience Testing):** كتابة سيناريوهات لاختبار سلوك النظام عند تعطل API المبيعات (503 Service Unavailable / Network Timeout) وضمان رد المساعد بلهجة عراقية مهذبة دون أعطال برمجية.
3. **توسيع بنك الأسئلة الشائعة في قاعدة المعرفة المحلية لفرع كربلاء.**
