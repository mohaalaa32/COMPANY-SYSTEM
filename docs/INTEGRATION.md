# دليل ربط الأنظمة الحقيقية — INTEGRATION GUIDE
**Tel Baghdad AI Sales Assistant (مساعد المبيعات الذكي لـ تل بغداد)**

تم تصميم نظام المحولات (Adapters) بحيث يفصل تماماً بين منطق المبيعات والذكاء الاصطناعي وبين واجهات برمجة التطبيقات (APIs) الحقيقية.
عندما تكون جاهزاً لربط نظام مبيعات الشركة الحقيقي وواتساب كلاود API، يمكنك إنجاز ذلك في 5 خطوات واضحة ومحددة.

---

## الجزء الأول: ربط نظام مبيعات الشركة (Company Sales API) في 5 خطوات

> **موعد البدء (Timeline):** يبدأ تطبيق الخطوة الأولى (I-1) بعد اعتماد اكتمال المرحلة 0 (Phase 0) وقبل الدخول في المرحلة 2 (Phase 2). عندها يتم طلب توثيق API الشركة وعينات البيانات وإعداداته الآمنة لفرع كربلاء عبر متغيرات البيئة `.env` دون مشاركة أي أسرار في المحادثة.

### الخطوة 1: الاتصال والمصادقة (Authentication & Connection - I-1)
- **المطلوب:** مفتاح الـ API، الرابط الأساسي (Base URL)، ورأس الطلبات (Headers).
- **التطبيق في الكود:** تعديل `packages/adapters/src/sales/real-sales-adapter.ts`.
- **المعايير:**
  - المهلة الزمنية (Timeout): 5 ثوانٍ لكل طلب.
  - سياسة إعادة المحاولة: 3 محاولات مع تأخير تصاعدي (Exponential Backoff).
  - التخزين المؤقت (Caching): 60 ثانية لبيانات المنتجات الثابتة.

### الخطوة 2: المنتجات والمواصفات (Products & Specs)
- **المطلوب:** مطابقة بنية المنتجات القادمة من الـ API الحقيقي مع واجهة `Product` في `packages/adapters/src/types.ts`.
- **التحويل (Mapping):**
  - مطابقة المعرف الفريد (`sku` أو `product_id`).
  - استخراج المواصفات (الرام، الذاكرة، الكاميرا، المعالج، الضمان).
  - ربط الوسوم (`tags`) لتسهيل اقتراحات الذكاء الاصطناعي (مثل: الألعاب، الطلاب، التصوير).

### الخطوة 3: الأسعار والمخزون الحي لفرع كربلاء (Prices & Stock — Karbala only)
- **النطاق:** هذا النشر يعمل بفرع واحد فقط هو **كربلاء** (`branch-karbala`). تُفرض الحدود في الخادم (طبقة الأدوات) ولا يُسمح للنموذج باختيار فرع آخر.
- **المطلوب:** تفعيل دالة `checkStock(productId, branchId)` لفرع كربلاء من API الشركة. إذا أعاد API بيانات فروع أخرى فيجب تجاهلها في المحوّل (I-3) وعدم تخزينها أو عرضها.
- **المعايير:**
  - التحقق الفوري من توفر القطع قبل تقديم أي وعود بالشراء للعميل.
  - عنوان الفرع ورقم هاتفه وساعات عمله **غير معرّفة** حالياً ولا يجوز اختلاقها؛ تُضاف فقط من بيانات الشركة المعتمدة.
  - بيانات فروع أخرى إن وُجدت في قاعدة بيانات دائمة: لا تُحذف تلقائياً، بل تُعطّل إتاحتها (فلترة بالمحوّل) ويُقترح أرشفتها بعد موافقة المالك.

### الخطوة 4: العروض والخصومات (Offers & Promotions)
- **المطلوب:** ربط دالة `getOffers()` لاسترجاع الخصومات النشطة من نظام الشركة.
- **الحماية:** التحقق من سريان العرض وربطه بمحرك الحسابات للتأكد من عدم انتهاك الحد الأدنى للهامش الربحي.

### الخطوة 5: حجز المخزون وإنشاء الطلب (Order Creation & Reservation)
- **المطلوب:** تفعيل دالتي `reserveStock` و `createOrder`.
- **المعايير:**
  - حجز القطعة لمدة 15 دقيقة ريثما يكتمل تأكيد العميل.
  - إرسال رقم الطلب الموحد وضمان عدم التكرار عبر `idempotencyKey`.

## الجزء الثاني: ربط WhatsApp Cloud API

1. **المتطلبات:**
   - معرف رقم الهاتف (Phone Number ID).
   - توكن وصول دائم (System User Permanent Token).
   - معرف حساب واتساب للأعمال (WABA ID).
2. **التطبيق في الكود:** تعديل `packages/adapters/src/whatsapp/real-whatsapp-adapter.ts`.
3. **قالب الرسالة:**
   - إرسال ملخص الطلب فور التأكيد:
     - رقم الطلب واسم العميل ورقم الهاتف والمحافظة والعنوان.
     - الأجهزة والإكسسوارات والكميات.
     - السعر الإجمالي بالدينار العراقي + أجور التوصيل.
4. **منع التكرار (Idempotency):** التحقق من أن رقم الطلب لم يرسل مسبقاً قبل استدعاء واجهة واتساب.
